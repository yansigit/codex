## Live check details

- **Cursor:** Browser OAuth and refresh passed. Refresh changed access, retained
  the refresh token and account generation, and cleared the pending state;
  discovery returned 256 models and text completed. Actual Codex CLI checks
  covered native read/write, shell, `ls`, `grep`, delete, ordinary exec/stdin,
  MCP text and image, file failure, policy denial, cancellation and resume.
  Interactive approval RPC decline left the target file absent and generation
  continued; acceptance wrote the expected file via the ordinary Codex host.
  The MCP image success used a temporary image-enabled model catalog; production
  default catalog support was added afterward and needs a current-binary rerun.
- **OpenCode Go:** `glm-5.3` Chat, `minimax-m3` Messages, and `gpt-6-luna`
  Responses passed live Codex tool and resume reads; model change to Messages
  passed. Branch/compaction passed without an explicit provider override.
  Approval denial and acceptance both followed the normal host permission
  path. Go Chat and Responses vision recognized the tested red PNG. Messages
  vision did not; the latest source adds an image-only result placeholder, but
  the full-core retest is pending. The original upstream Go key exhausted its
  monthly quota; tests explicitly selected `opencode_go_1` with no fallback.
- **Claude:** `claude-haiku-5-5` passed interactive browser OAuth, 14-model
  discovery, refresh, reasoning, core `view_image`, tool continuation, and
  resumed reads. Model change to `claude-sonnet-4-6`, branch/compaction,
  approval denial/acceptance, and TUI status/model/account presentation passed.
  Image vision identified the tested red PNG.
- **Antigravity:** Browser OAuth and discovery (26 models) passed. Native Rust
  Gemini and Claude-family zero-argument image-tool loops completed and
  identified the tested red PNG. Model change and branch/compaction passed;
  normal Codex approval denial/acceptance passed. Full-core image verification
  awaits the latest build.

## Evidence boundaries

- These results cover only tested accounts, models, calls, and dates. They do
  not establish provider entitlement or catalog-wide compatibility.
- Passing approval paths do not prove every policy branch or every platform.
- Image support is route-specific: the Go Messages color error and pending
  current-build reruns prevent a broad multimodal-complete claim.
- Build, clippy, and feature checks are in progress. No provider is marked
  complete until final gates and the listed acceptance follow-ups pass.
